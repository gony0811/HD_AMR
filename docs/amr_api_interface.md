1.1. REST API 전체 사양서 (JSON 또는 문서) 제공 가능 여부 — 예시) 전체 엔드포인트 목록, 인증 방식, 기본 포트 등

/api/v3 로 접속하시면 실 로봇과 연동되는 페이지에서 인터페이스 테스트 해보실 수 있습니다.



별도 인증은 없으며, 80포트 사용하고 있습니다.



&#x20;



2.1. 응답 스키마 — 성공/실패 시 각각 어떤 body가 반환되는지.



성공시 : {code: 0, data: {}}



실패시 : {code: N, message: “”}



&#x20;



2.2. 동기/비동기— 응답이 "명령 수리"인지 "도착 완료"인지. 비동기라면 이동 완료/실패를 확인하는 방법(상태 조회 엔드포인트? 콜백?).

기본적으로는 명령 수리입니다.



GET /api/v3/robot/status 에서 schedule 필드 상태로 확인 가능합니다.



&#x20;



2.3. 이동 실패 시 동작— 목표 도달 불가(장애물·경로 없음) 시 로봇 동작과 실패 통지 방법, 관련 에러코드 목록.

GET /api/v3/robot/status 에서 error 필드 상태로 확인 가능합니다.



&#x20;



2.4. stopFlag 의미 — true/false 각각의 동작.

True: 해당 지점에 정차하고 각도까지 보정



False: 해당 지점 근처에서 정차하고 바로 다음 목적지로 이동



&#x20;



2.5. 좌표 프레임 — x/y\[m], rz\[rad] 가 SLAM 맵 원점 기준이 맞는지, rz가 맵 X축 기준 CCW 라디안인지.

SLAM 맵 원점기준이며, 원점은 좌측 하단입니다.



RZ는 X축기준 CCW 라디안 맞습니다.





2.6. 이동 중 재호출 — 이동 중 새 `/go` 호출 시 동작(대체? 또는 거부?).

이동작업을 추가 등록하는 메소드로, 다음 목적지가 등록됩니다

중간에 이동을 멈추고 다른 목적지로 보내려면 POST /api/v3/robot/state 호출이 필요합니다



&#x20;



2.7. 이동 중지 — REST로 진행 중 이동을 중지하는 엔드포인트 유무. 없다면 Modbus 주행 정지(Holding 12)가 REST 발행 이동도 정지시키는지.

POST /api/v3/robot/state 호출 (api/v3 문서에서 예제 참고)



&#x20;



3.1. 배경: 화물창 4개 층을 각각 스캔한 맵을 1장의 맵으로 병합해(층별 타일 배치) 단일 맵으로 만들어서 해당 층에 이동했을때 재측위(InitPose)를 실행해서 층 전환을 하려고 합니다.



&#x20;                                (이전에 교육때 층 단위 맵관리를 이런식으로 하면된다고 의견주셨던 기억이 있습니다.)

가능합니다. 권장하는 맵 크기는 200m x 200m 이하입니다. (40000m^2 이하)



&#x20;



3.2 각 층별 맵을 작성하고 맵 에디터로 맵을 복사 붙여넣기 하는 식으로 통합맵을 만드는게 맞는지. 혹 다른 방법이 있는지 문의 드립니다.

맞습니다.

먼저 각각 구역의 맵을 스캔해서 생성하고, 모든 구역을 포함하는 통합 맵을 생성한 후에, 그 위에서 각 거점등을 추가해야 합니다.
