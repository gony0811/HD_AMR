# 지워진 공구(tool) 좌표계 정의 복원

날짜: 2026-09-21
대상: FAIRINO 코봇 공구 좌표계, Desktop 코봇 화면 `공구 정의 복원 (교시 위치 기반)`

## 배경

컨트롤러의 공구 좌표계(예: tool 1)를 실수로 지우면 그 정의 [x,y,z,rx,ry,rz] 는 앱 어디에도 남아 있지 않다.
공구 좌표를 쓰는 경로(코봇 화면 수동 입력, 레이저 TCP 터치 결과 쓰기)는 값을 파일·DB·로그에 기록하지 않는다.

그러나 **교시 위치**(`TeachingPositions`)는 캡처 당시의 TCP pose(그 공구 기준, BASE 좌표)와 관절각 J1~J6 을
함께 저장한다. 같은 관절각에서 플랜지(tool 0) pose 를 컨트롤러 정기구학으로 구하면 공구 오프셋이 그대로 나온다.

```text
T_TCP = T_플랜지 · offset   →   offset = inv(T_플랜지) · T_TCP
```

회전(rx, ry, rz)까지 복원되고, 로봇을 움직일 필요가 없다.

## 절차

1. 코봇 연결 후 **코봇** 화면 → `좌표계 변경` 카드 → `번호(id)` 를 복원할 공구 번호(예: 1)로 맞춘다.
2. `공구 정의 복원 (교시 위치 기반)` 을 펼치고 `교시 위치로 공구 오프셋 복원` 을 누른다.
   - 그 공구로 캡처된(관절각 포함) 교시 위치마다 오프셋 한 줄이 나온다(최신 캡처 순).
   - 요약에 행 간 차이(위치 mm / 회전 °)와 권장값(최신 행)이 표시된다.
3. 행 간 값이 **0.5 mm / 0.1° 이내로 일치**하면 그 값이 지워진 정의다. 어긋나면 그 사이에 공구를 재정의한
   것이므로 가장 최근 행을 쓴다.
4. 원하는 행의 `편집란에 적용` → X~Rz 값을 확인 → `공구 좌표계 설정` 으로 컨트롤러에 쓴다(자동 쓰기는 없다).
5. `공구 불러오기` 로 컨트롤러 값을 다시 읽어 확인하고, 조그 +X 10 mm 가 정확히 10 mm 움직이는지로 마무리한다.

## 한계

- 공구 **하중**(질량·무게중심)과 설치 방향 같은 부가 설정은 복원되지 않는다. 펜던트에서 다시 입력한다.
- 교시 위치가 하나뿐이면 교차 검증이 없다. 조그 정확도로 확인한다.
- 컨트롤러 정기구학(`GetForwardKin`)이 필요하므로 코봇이 연결돼 있어야 한다.

## 권고

공구를 정의·수정할 때마다 그 값을 기록해 두면 이 절차가 필요 없다. 펜던트의 시스템 백업을 받아 두거나,
코봇 화면에서 `공구 불러오기` 한 값을 메모해 둔다.

## 구현

- `FairinoRpcClient.GetToolPoseInBaseAtJointsAsync(joints, tool)` — 임의 관절각에서의 공구 pose(무모션). tool 0 = 플랜지.
- `ToolOffsetRecoveryService` — 교시 위치 수집, `ComputeOffset`(순수 함수), 행 간 일치도, 권장값.
- `CobotViewModel.RecoverToolOffset` / `ApplyRecovered` — Desktop 화면.
