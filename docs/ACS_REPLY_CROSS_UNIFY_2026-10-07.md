## 0. 결론 요약

CROSS3/CROSS4 를 **면별 분류 없이 통합**하려면, 네 질의를 전부 **면-로컬 (u,v) 프레임** 기준으로 못박으면 됩니다. 전개도(ACS 도면) 기준으로 정의하면 전개 시 일부 면이 거울 반전되어 손잡이(handedness)가 뒤집히므로 면 무관성이 깨집니다.

**면-로컬 프레임 정의** (10면 어디서나 노드 theta + 면 법선으로 재구성 — `SeamDirectionResolver` 규약):
- **u** = 노드 theta(벽 정면 방향)의 좌회전 90° 수평벡터 = **(−sinθ, cosθ)**
- **v** = **n × u** (면내 수직축)
- **n** = 면 외향 법선 (AMR/카메라를 향함)

| # | 질의 | HD_AMR 확정안 | ACS 액션 |
|---|------|--------------|----------|
| 1 | CROSS3 R0 기준 | **줄기(stem)가 +u** (통과선 아님) | 사인오프 |
| 2 | 회전 부호 | **면 외향 법선 둘레 CCW(+)**, 작업물 좌표 기준 | 사인오프 |
| 3 | `params.points` | 면-로컬 (u,v) mm·원점=중심·CCW 순·arm별 길이·**비실행 참조값** | 사인오프 |
| 4 | 정차 재현성 | **거친 정면 정차 + wobj 정렬 흡수** — ACS 는 리치/FOV 만 보장 | 확인(ACS 부담 없음) |

## 1. CROSS3 R0 기준 자세 — **줄기 = +u**

**R0 ≡ 줄기(stem)가 면-로컬 +u 를 가리키는 자세.** (R0 에서 통과선은 ±v.)

- **통과선이 아니라 줄기로 정의**합니다. 통과선은 180° 대칭이라 R0 와 R180 을 구별하지 못합니다. 줄기가 대칭을 깨고 R0/R90/R180/R270 네 회전을 유일하게 결정합니다.
- 기준축은 전역 "선수(bow)"가 아니라 **면-로컬 +u** 입니다. u 는 면마다 theta+법선으로 재구성되므로, 선수와 일치하는지는 면에 따라 다릅니다 — "선수" 라벨링은 쓰지 않습니다.

## 2. 회전 부호 — **법선 둘레 CCW(+), 작업물 좌표 기준**

**R90 = R0 에서 면 외향 법선 둘레 CCW(좌회전) 90°**, AMR 작업물 좌표(카메라가 면을 바라보는 시점) 기준.

- HD_AMR 코드 규약 전체가 **법선 둘레 CCW 양(+)**(theta = 맵 X축 CCW, u = theta 좌회전 90°)이라 이와 일치시킵니다.
- 각 면의 외향 법선은 AMR 을 향하므로 "카메라가 보는 CCW"는 10면에서 일관됩니다.
- **ACS 전개도 기준이 아니라 AMR 작업물 좌표 기준**으로 고정합니다(전개도는 거울 반전으로 부호가 뒤집힘).

## 3. `params.points` 의미·순서·좌표계

- **좌표계**: **면-로컬 (u,v), 단위 mm, 원점 = 교차 중심.** (맵 좌표 아님 — ACS 가 도면에서 바로 추출 가능하고 면 무관.)
- **CROSS4** = 끝점 4개, 순서 **+u → +v → −u → −v (CCW, §2 부호와 일치)**. 각 점의 원점 거리 = 해당 arm 길이 → **arm별 길이 개별 반영(Yes)**.
- **CROSS3** = 3점, 순서 **[줄기 끝(R0 에서 +u) · 통과선 +v · 통과선 −v]**. 첫 점(줄기)이 R 을 유일하게 결정.

> ⚠️ **중요 — points 는 실행 궤적이 아닙니다.** HD_AMR 실행은 ACS 가 보낸 점을 따라가지 않고, `/inspection-points` 에서 6-DOF 캡처 교시한 절대 프로필(`PoseAbsolute`)을 등록된 작업물 좌표계 안에서 순회합니다(코로게이션 법선·깊이 반영, 패턴 수식 생성 경로는 제거됨). 따라서 `params.points` 는 **(a) 교시 시작 템플릿 시드, (b) arm 개수·대략 기하·비전 메타 참조값**으로만 씁니다. 정밀도 책임은 ACS 가 아니라 AMR 캡처 교시에 있습니다.

## 4. 중심(정차) 재현성 — **거친 정면 정차 + 작업물 좌표계 정렬로 흡수**

**교차부(면 중심) 정면에 거칠게 정차한 뒤, 작업물 좌표계(wobj 3점 등록) 정렬로 잔여 오차를 흡수**합니다(후자).

- AMR 은 `seamStartW` → 코봇 BASE 로 **거친 접근**만 하고, 정밀은 정렬 체인(wobj 3점 등록)이 담당합니다. 캡처 프로필은 **맵이 아니라 등록된 작업물 프레임 기준**으로 실행되므로 정차 오차를 흡수합니다(단일 상대 원칙).
- **ACS 요건**: `seamStartW` + `standoffMm` 로 **교차부가 리치·FOV 안에 들어오도록**만 보장하면 됩니다. **정차 반복 정밀도는 ACS 책임이 아닙니다** — AMR 정렬이 보장합니다.
- 참고: `anchorGroupId` 공유로 정렬(⑤~⑯)을 재사용해도, 검사위치 이동·카메라 거리·평탄면 센터링(②③④)은 액션마다 `seamStartW` 가 달라 매번 재수행합니다.

## 5. 참고 — 비전 메타(질의 외 관련 항목)

CROSS 교차 arm 의 90° 회전 영상에 대한 **비전측 별도 메타 구분은 불요**하다고 봅니다 — 경유점별 툴 회전(`RzDeg`)·표면 형상(`Surface`)을 캡처 프로필이 담아 CAPTURE_REQ 로 중계합니다. 비전팀 확인만 요청드립니다.

---

## 6. ACS 사인오프 요청 항목

1. **CROSS3 seamType 4값**: `CROSS3_R0` / `CROSS3_R90` / `CROSS3_R180` / `CROSS3_R270` 로 발행 전환 (현재 AMR 은 legacy bare `CROSS3` → `CROSS3_R0` 별칭 수용 중).
2. **R0 기준** = 줄기가 면-로컬 +u (§1).
3. **회전 부호** = 면 외향 법선 둘레 CCW, 작업물 좌표 기준 (§2).
4. **`params.points`** = 면-로컬 (u,v) mm·원점=중심·CCW 순·arm별 길이, 비실행 참조값 (§3).

> HD_AMR 측(파서·resolver·16종 레시피 시드·`/inspection-points` UI·테스트)은 위 정의로 반영 완료. ACS 사인오프 후 실기 E2E 검증 및 게이트 활성화 예정.
