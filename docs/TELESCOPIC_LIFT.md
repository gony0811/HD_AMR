# Z축 리프트 (텔레스코픽) — RS232/TTL 프로토콜

코봇을 올리는 Z축 텔레스코픽 컬럼(약 1000 mm 행정)의 **EBLUM 3채널 홀 동기 컨트롤러** 연동.

- **사양서**: `docs/RS232TTL Communication Protocol (Three-Channel Hall Synchronous Controller).xlsx`
- **화면**: Desktop `SETTINGS ▸ Lift` ([LiftView.axaml](../src/HD.AMR.Desktop/Views/LiftView.axaml))
- **프로토콜(순수)**: [`TelescopicProtocol`](../src/HD.AMR.App/Communication/TelescopicProtocol.cs) — 시리얼을 안 타므로 전 플랫폼에서 테스트된다
- **통신·안전**: [`TelescopicClient`](../src/HD.AMR.App/Communication/TelescopicClient.cs) / [`TelescopicService`](../src/HD.AMR.App/Service/TelescopicService.cs)
- **설정**: `appsettings.json` 의 `"Telescopic"` 섹션

관련: [TAB_CALIBRATION.md](TAB_CALIBRATION.md) — 리프트 높이는 `T_A_B` 의 `tz` 를 직접 바꾸므로 캘리브레이션과 직결된다.

---

## 1. 물리 계층

| 항목 | 값 |
|---|---|
| 보율 / 형식 | 9600, 8 데이터비트, 1 스톱비트, 패리티 없음 |
| 레벨 | **TTL** — PC 연결 시 TTL↔RS232(또는 TTL↔USB) 변환 모듈 필요 |
| 커넥터 | RJ45 8핀 |
| 종단 저항 | 통신 포트에 120Ω 내장 |

RJ45 핀맵 (컨트롤러 측 Female, 걸쇠 아래·정면 기준 좌→우 1~8번):

| 핀 | 신호 | 비고 |
|---:|---|---|
| 1 | CAN_L | CAN 버스(본 연동 미사용) |
| 2 | CAN_H | |
| 3 | RX1 | 컨트롤러 **수신** — 외부 기기 TX 에 연결 |
| 4 | TX1 | 컨트롤러 **송신** — 외부 기기 RX 에 연결 |
| 5 | RX4 | 보조 채널 |
| 6 | TX4 | |
| 7 | 5V | 전원 |
| 8 | GND | 공통 접지 — 반드시 연결 |

> ⚠ TX/RX 는 **교차** 결선한다. 전원(7)이 통신 핀과 단락되지 않았는지 확인한 뒤 전원을 넣는다.

## 2. 명령 체계

문답식이고 모든 명령은 `\r\n`(0x0D 0x0A)으로 끝난다. **컨트롤러는 상태를 자동 통보하지 않는다** — 반드시 조회해야 한다(사양서 FAQ 4).

### 2.1 제어 — `Handle:NNN`

`NNN` 은 3바이트 **10진 문자열**이고 컨트롤러가 이를 8비트 비트마스크로 해석한다.

| 비트 | 값 | 기능 |
|---|---:|---|
| Bit0 | 1 | 상승 |
| Bit1 | 2 | 하강 |
| Bit2 | 4 | 메모리 위치 1 |
| Bit3 | 8 | 메모리 위치 2 |
| Bit4 | 16 | 메모리 위치 3 |
| Bit5 | 32 | 추진기 리셋 |

| 동작 | 명령 | HEX |
|---|---|---|
| 상승 | `Handle:001` | `48 61 6E 64 6C 65 3A 30 30 31 0D 0A` |
| 하강 | `Handle:002` | `48 61 6E 64 6C 65 3A 30 30 32 0D 0A` |
| 정지 | `Handle:000` | `48 61 6E 64 6C 65 3A 30 30 30 0D 0A` |
| 리셋 | `Handle:032` → 2초 유지 → `Handle:000` | `… 30 33 32 …` |
| 메모리 n **이동** | `Handle:004/008/016` → **50 ms** → `Handle:000` | |
| 메모리 n **저장** | `Handle:004/008/016` → **2 s** → `Handle:000` | |

메모리는 이동과 저장이 **같은 명령이고 유지 시간으로만 구분**된다. 이 값들은 회귀 테스트로 고정돼 있다.

### 2.2 지정 높이 — `Target:NNN` → `Target:X`

`X` = 0 실행 가능 / 1 실행 불가(잠김·슬립 등).

> ⚠ **미확정**: 사양서는 지령 높이를 **3바이트(0~999 mm)** 로 규정하는데 응답 높이는 **4바이트**다.
> 행정이 1000 mm 이면 3자리로 최상단을 지령할 수 없다. 벤더 확인 대상이며, 확인되면
> `appsettings.json` 의 `Telescopic:TargetDigits` 를 4로 올리면 된다(코드 변경 불필요).

### 2.3 상태 조회 — `Read` → `Length:…`

페이로드 14자: 활성(1) + 운행모드(1) + 잠금(1) + 단위(1) + 소리(1) + 파라미터플래그(1) + 파라미터모드(1) + 높이깜빡임(1) + 에러코드(2) + 높이(4).

에러·높이는 **뒤에서 세어** 읽으므로 중간 필드 개수가 다른 펌웨어 변종에도 어긋나지 않는다. 길이가 14가 아니면 화면에 "응답 길이 불일치" 경고가 뜨고 중간 필드는 신뢰하지 않는다.

| 필드 | 값 |
|---|---|
| 활성 | 0 슬립 / 1 활성 |
| 운행 모드 | 0 정지, 1 상승, 2 하강, 3 리셋, 4 메모리 이동, 5 장애물 후퇴 |
| 잠금 | 0 잠김 / 1 해제 |
| 단위 | 0 mm / 1 inch |

### 2.4 에러 클리어 — `ClearErr` → `ClearErr OK`

에러 코드: 0 정상, 1 장애물 후퇴, 2 과전압, 3 저전압, 4 기울기, 5 통신 중단, 6~8 모터 A/B/C 과전류, 9~11 홀 A/B/C 무신호, 12 모터 과열, 13 전원 과전류, 14 자세 시간 초과, 15 미등록, 16 모터 하강(슬립).

## 3. 안전 설계

**이 화면은 코봇을 얹은 1 m 리프트를 실제로 움직인다.** 프로토콜의 상승/하강은 "명령 유지" 방식이라 정지 명령을 보내지 않으면 리미트까지 계속 간다. 그래서 다층으로 막는다:

| 계층 | 장치 |
|---|---|
| UI | 상승/하강은 **누르고 있는 동안만**(hold-to-move). 떼기·포인터 이탈·캡처 상실·화면 이탈 전부 정지로 연결 |
| UI | 모든 동작 명령은 **"동작 허용" 체크** 후에만 활성. 정지 버튼만 예외로 항상 활성 |
| 서비스 | **데드맨** — UI 유지 신호가 `JogDeadmanMs`(기본 700 ms) 끊기면 자동 정지 |
| 서비스 | 1회 연속 조그 상한 `JogMaxDurationMs`(기본 30 s) |
| 서비스 | 앱 종료 시 정지 명령 |
| 컨트롤러 | 통신 중단 알람(에러 05), 장애물 감지 후퇴 |

유지 명령을 반복 전송해도 무해하다(사양서 FAQ 1). 조그와 `Target` 절대 이동은 섞지 않는다 — 절대 이동 전에 조그 세션을 먼저 끝낸다.

> 물리 정지 버튼이 최종 방어선이다. 소프트웨어 정지가 실패하면 화면이 그렇게 안내한다.

## 4. T_A_B 와의 관계

리프트 높이는 `T_A_B` 의 `tz` 를 직접 바꾼다 — `tz(s) = tz0 + s`, `tz0` = 완전 하강 기준.
런타임 보정은 [`MapCalibration.MountPoseAtStroke`](../src/HD.AMR.App/Service/MapCalibration.cs).

장착 보정 화면은 이제 컨트롤러가 보고한 높이를 **"리프트에서 읽기"** 버튼으로 가져올 수 있고,
입력한 스트로크가 실측과 1 mm 넘게 다르면 경고한다. 표본 간 스트로크 편차 1 mm 가 기울기 0.32° 오차를
만들기 때문이다([TAB_CALIBRATION.md §2](TAB_CALIBRATION.md)).

## 5. 미확정 / 제약

1. **`Target` 3바이트 vs 응답 4바이트 비대칭** — §2.2. 벤더 확인 필요.
2. **컨트롤러 높이의 원점** — 보고 높이가 기계적 원점(완전 하강)에서 0 인지, 별도 기준인지 실기 확인 필요.
   완전 하강 상태에서 `Read` 해 보면 바로 알 수 있다. 0 이 아니면 `tz0` 계산 시 그 오프셋을 빼야 한다.
3. **상승/하강 리미트·속도는 통신으로 설정 불가** — 전용 산업용 디버깅 화면 필요(FAQ 6).
4. **CAN 채널(핀 1·2)과 RX4/TX4(핀 5·6)는 미사용** — 필요해지면 별도 확인.
5. 사양서 FAQ 는 CRC 검증을 언급하지만 RS232/TTL 명령 형식에는 **체크섬이 없다**(Modbus 경로 설명으로 보인다).
   통신 오류는 응답 형식 검증과 타임아웃으로만 걸러진다.

- `cd src && dotnet test HD.AMR.sln` — [`TelescopicProtocolTests`](../src/HD.AMR.Tests/TelescopicProtocolTests.cs)
  가 명령 문자열을 **사양서 HEX 원문과 바이트 단위로** 대조하고, 응답 파싱·에러 이름·유지 시간을 고정한다.

- 포트가 없는 환경에서는 서비스가 경고 1회만 남기고 조용히 재시도한다(macOS 에서 확인).
- **실기 체크리스트**: 변환 모듈 결선 확인 → `Read` 응답 수신 → 에러 0 확인 → 짧은 조그로 방향 확인
  (상승 버튼이 실제로 올라가는지) → 완전 하강 시 보고 높이 확인(§5-2) → `Target` 소폭 이동 → 메모리 저장/이동.
