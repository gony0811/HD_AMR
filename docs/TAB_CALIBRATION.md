# 코봇 장착 보정 (T_A_B) 절차서

AMR 차체 프레임 **A** → 코봇 BASE 프레임 **B** 장착 변환 **T_A_B** 를 고정 표적 터치로 산출하는 절차.

- **화면**: Desktop `SETTINGS ▸ 장착 보정 (접촉식)` ([MountCalibrationView.axaml](../src/HD.AMR.Desktop/Views/MountCalibrationView.axaml))
- **수학**: [`MapCalibration.SolveMount3D`](../src/HD.AMR.App/Service/MapCalibration.cs)
- **저장**: `Calib.Mount.Pose`(적용값) / `Calib.Mount.SolveJson`(측정값) / `Calib.Mount.SamplesJson` / `Calib.Mount.TargetZmm`
  — 전부 `Parameters` 테이블. `/parameter` 화면에서 그대로 보인다.

T_A_B 는 좌표 체인의 뿌리다(`p_W = T_W_A · T_A_B · p_B`). 오차는 목표 SLAM pose 오차로 그대로 전파되므로
QR 정차 티칭보다 **먼저** 확정해야 한다.

> **이 문서는 접촉식 방법이다.** 운영 표준은 카메라 기반
> [`장착 보정 (ArUco)`](ARUCO_TAB_CALIBRATION.md) 이고, 둘은 같은 `T_A_B` 를 구하는 **대안**이다
> (둘 다 `Calib.Mount.Pose` 에 쓴다).
>
> 접촉식을 남겨 둔 이유는 **오차 체인이 짧고 카메라가 전혀 필요 없다**는 것이다 —
> 접촉식은 `T_B_T` 변환 하나, ArUco 는 `T_B_T · T_T_C · T_C_Q` 세 개다. ArUco 쪽 `T_T_C` 오차는
> `T_A_B` 로 흡수되어 잔차로 드러나지 않으므로, **ArUco 결과를 독립적으로 교차검증할 수 있는 유일한 수단**이다.
> 초기 도입 시 한 번은 두 방법을 대조해 보라(권장 일치 범위: tx·ty ±25 mm, rz ±1.5°, 기울기 ±0.3°).

## 1. 원리와 관측 가능성

고정 세계점 `q` 를 여러 AMR 자세에서 코봇 TCP 로 터치하면 `q = T_W_A(k) · T_A_B · p_k` 이고,
AMR pose 는 평면(yaw θ, z=0, roll=pitch=0)이다. `R = Rz(rz)·M`, `M = Ry(ry)·Rx(rx)` 로 쪼개면 z 식이 분리된다:

```
q_z = r3·p_k + t_z ,   r3 = R의 3행 = (−sin ry, cos ry·sin rx, cos ry·cos rx)
```

| DoF | 관측 | 산출 방법 |
|---|---|---|
| rx, ry | 가능 | 터치점 `p_k` 는 BASE 에서 법선 `r3` 인 **한 평면 위**에 놓인다 → 총최소자승 평면 적합 |
| rz, tx, ty | 가능 | `Rz` 는 z 를 섞지 않으므로 xy 식이 기존 평면 문제와 동일 → 터치점을 `M` 으로 선회전해 `SolveMount2D` 위임 |
| **tz** | **불가** | z 식에서 `t_z` 는 언제나 미지의 `q_z` 와 `d = q_z − t_z` 로만 묶인다 |

> **tz 는 표적 높이 입력 없이는 결정되지 않는다.** 표적을 하나 더 두어도 미지수가 하나 같이 늘 뿐이다.
> 운영자가 `q_z`(바닥 기준 표적 높이 — 바닥에 두면 **0**)를 재서 입력하면 `tz = q_z − d` 로 닫힌다.
> 화면은 이 값을 별도 카드로 두고 확인 체크박스를 요구한다.

### 기준면은 바닥이다

A 프레임 원점의 높이는 로봇에서 재는 값이 아니라 **정하는 값**이다 — `AmrPoseToMmDeg` 가 `T_W_A` 의 z 를
항상 0 으로 강제하므로 A 원점 평면 = 맵 z=0 평면이고, 시스템 어디에도 절대 높이를 관측하는 곳이 없다.

**바닥면을 z=0 으로 쓴다.** 코봇 베이스면을 기준으로 잡으면 안 되는 이유는 편의가 아니라 정합성이다 —
베이스는 Z축 텔레스코픽 위에 있어 약 1000 mm 를 오르내리므로, 기준면으로 삼으면 A 원점이 차체에 대해
움직여 `T_A_B` 가 변환이 아니게 된다. 바닥면은 차체에 대해 고정이다.

따라서:

- `q_z` = 표적의 바닥 기준 높이 — **계산하는 값이 아니라 줄자로 잰 값을 그대로 넣는다**
  (바닥에 두면 0, 770 mm 받침 위에 두면 770)
- `tz` = 코봇 베이스의 바닥 기준 높이 — 줄자로 직접 검증 가능한 유일한 물리 측정
- QR 바닥 마커 `Zmm` = 0, 도면 z=0 = 바닥

교차 확인은 `QrLocalization.SolveAmrPose` 의 `ZResidMm` 이 한다 — 기준면이 일관되면 0 근처,
어긋나면 그 차이가 mm 로 그대로 찍힌다.

`q_z` 를 나중에 입력해도 **재터치가 필요 없다** — `Calib.Mount.SolveJson` 에 `d` 가 남아 있다.

### 정밀도 특성 — 두 채널이 완전히 다르다

z 방정식에는 AMR pose 가 **전혀 들어가지 않는다**. 따라서:

| 값 | 지배 오차원 | 기대 정밀도 |
|---|---|---|
| rx, ry | 터치 반복도(≈1 mm)와 터치점 펼침만 | ±0.05 ~ 0.2° |
| rz | SLAM pose 잡음 | ±0.5 ~ 1.5° |
| tx, ty | SLAM pose 잡음(√N 로만 개선) | ±10 ~ 25 mm |
| tz | 입력한 `q_z` 정확도와 1:1 | 입력값 나름 |

그래서 화면은 잔차를 **터치(평면) RMS** 와 **SLAM(평면내) RMS** 로 나눠 보여 준다.
평면 RMS 가 2 mm 를 넘으면 접촉 문제, 평면내 RMS 가 25 mm 를 넘으면 SLAM/정차 문제다.

## 2. Z축 텔레스코픽 — tz 는 상수가 아니다

코봇 BASE 가 약 1000 mm 행정의 Z축 텔레스코픽 위에 있다. 승강축이 AMR 차체 Z 와 평행하므로
**변하는 성분은 tz 하나뿐**이다:

```
tz(s) = tz0 + s      tz0 = 완전 하강(기계적 원점) 시 코봇 베이스의 바닥 기준 높이
                     s   = 현재 스트로크 (RS232/TTL 로 컨트롤러에서 읽음)
```

구조적으로 잘 맞아떨어진다 — 솔버가 **관측할 수 있는 5자유도(tx·ty·rx·ry·rz)가 정확히 스트로크와
무관한 상수**이고, 관측 못 하는 tz 가 정확히 변하는 값이다. 그래서 캘리브레이션 한 번으로 상수부가 전부 확정된다.

런타임 보정은 [`MapCalibration.MountPoseAtStroke`](../src/HD.AMR.App/Service/MapCalibration.cs) 를 쓴다.

텔레스코픽 통신(RS232/TTL)은 구현돼 있다 — [TELESCOPIC_LIFT.md](TELESCOPIC_LIFT.md), `SETTINGS ▸ Lift` 화면.
장착 보정 화면의 **"리프트에서 읽기"** 버튼이 컨트롤러가 보고한 현재 높이를 스트로크 입력란에 채우고,
입력값이 실측과 1 mm 넘게 다르면 경고한다(오타 한 번이 기울기를 통째로 틀어뜨리기 때문).

> ⚠ 컨트롤러 보고 높이의 원점이 기계적 원점(완전 하강)에서 0 인지는 **실기 확인 대상**이다
> (TELESCOPIC_LIFT.md §5-2). 0 이 아니면 그 오프셋을 빼고 `tz0` 를 계산해야 한다.

### 전 표본을 같은 스트로크에서 잡아야 한다

산출은 터치점이 **한 평면 위에 놓인다**고 가정한다. 스트로크가 표본마다 다르면 터치점이 `−s_k` 만큼
어긋난 평면들에 놓이고, 그 편차가 **전부 가짜 기울기로 흡수**된다.

| 표본 간 스트로크 편차 | 가짜 기울기 (면내 펼침 180 mm 기준) |
|---:|---:|
| 1 mm | 0.32° |
| 10 mm | 3.2° |

터치 잡음 1 mm 와 같은 크기의 오차를 스트로크 1 mm 편차가 만든다. 제어하지 않으면 **최대 오차원**이 된다.
그래서 `CalibrationService.SolveMount3D` 가 표본 간 스트로크 편차 1 mm 초과를 **계산 전에 거부**하고,
화면은 캡처 전에 스트로크 확인 체크를 요구한다. 잔차로는 전혀 드러나지 않기 때문이다.

### 컬럼 수직도 확인 (권장)

컬럼이 완벽히 수직이 아니면 tx·ty 도 스트로크에 약하게 의존한다(1 m 컬럼이 0.1° 기울면 완전 상승 시
약 1.75 mm 횡편차). **완전 하강과 완전 상승에서 각각 캘리브레이션해 tx·ty·rz 가 일치하는지** 확인하고,
다르면 `Δ(tx,ty)/Δs` 가 그 기울기를 직접 준다. 현재 구조로 바로 할 수 있는 검증이다.

## 2-1. 표적은 하나의 물리적 점이다 — 옮기면 예전 표본은 전부 무효

모든 표본은 **같은 물리적 점**을 터치해야 한다. 표적을 옮기면(또는 높이를 바꾸면) 기존 표본은
쓰레기가 되는데 **잔차만으로는 드러나지 않는다** — 해가 조용히 무의미해진다.

그래서 표본에 그때의 `q_z` 를 박아 둔다(`MountSample.TargetZmm`). 재시작 후에도 검출된다:

| 상황 | 동작 |
|---|---|
| 표본 간 기록된 표적 높이가 1 mm 넘게 다름 | `CalibrationService.SolveMount3D` 가 **계산 전에 거부** |
| 현재 입력 `q_z` 가 표본 기록과 다름 | 화면이 경고하고 **캡처·산출을 막는다** → '전체 삭제' 유도 |
| 표적 높이 미기록(구버전 표본) | 경고 — 같은 점이었는지 확인할 근거가 없다 |

화면은 현재 `q_z` 와 실측 `Bz` 로 **역산한 `tz` 를 표시**한다(`tz ≈ q_z − Bz`). 도면·줄자와 바로 대조하는
확인용이다. 예: 표적 770 mm, 새 터치에서 `Bz ≈ +32` → `tz ≈ 738 mm`.

> 초기 버전에 있던 "CAD tz 로부터 계산" 버튼은 **제거했다.** 바닥 기준으로 정한 뒤에는 `q_z` 가 직접
> 측정값이라 역산이 필요 없고, CAD tz 를 비워 둔 채 누르면 예전 표본의 평균 `Bz` 가 그대로 `q_z` 로
> 들어가 그럴듯하지만 틀린 값을 만들었다.

## 2-1-1. 표적 지시 방법 — 접촉식 / 카메라 포인팅

솔버가 요구하는 것은 "같은 고정점이 **BASE 좌표계에서 어디인가**"(`p_B`)뿐이다. 그 점을 어떻게 지시하든
`GetTcpPoseInBaseAsync(tool)` 가 그 위치를 주기만 하면 된다.

| 방법 | 성립 조건 | 지배 오차 |
|---|---|---|
| **접촉식** | 팁 TCP 가 캘리브레이션돼 있을 것 | 접촉 반복도 ±0.5~1.5 mm |
| **카메라 포인팅** | 해당 tool 의 **TCP 가 초점 위치**에 정의돼 있을 것 + 십자를 **화면 중앙 정렬** | 포커스 재현도(피사계 심도) |

> ⚠ 카메라 포인팅에서 **TCP 가 초점이 아니라 카메라 광학 원점이면** 작동거리만큼 standoff 가 생기고,
> 그 상수 오프셋은 `R·p_k + t` 에서 **병진 `t` 에 그대로 흡수**된다 — RMS·기울기는 멀쩡한데 tx/ty/tz 만
> 통째로 틀린다. **잔차로는 절대 드러나지 않는다.** 화면의 역산 `tz` 를 도면·줄자와 대조하는 것이
> 유일한 검출 수단이다. (tool 0/1 혼용과 같은 종류의 함정이다.)

**포커스만으로는 점이 정의되지 않는다.** 3D 점에는 구속 3개가 필요한데 포커스는 깊이 1개뿐이고
나머지 2개는 십자를 화면 중앙에 맞춰야 나온다. "중앙 = 광축 위"가 성립하려면 tool 의 Z 축이 광축이어야 한다.

### 벽 십자 + 수평 카메라는 오차 배분이 유리하다

| 오차원 | 방향 | 영향 | 평가 |
|---|---|---|---|
| 포커스(심도) | 광축 = 수평 | tx·ty·rz | 이미 SLAM 잡음(10~25 mm)이 지배 → 묻힌다 |
| 화면 중앙 정렬 | 상면(수직 포함) | **rx·ry** | 픽셀 단위 → 접촉보다 정밀할 수 있다 |

기울기는 터치점의 **수직** 정확도가 결정하므로, 약한 축(포커스)이 하필 SLAM 지배 영역으로 가는
이 배치는 기울기 정밀도 면에서 접촉식보다 나을 수 있다. 또 표적이 1~2 m 떨어져 있으면 AMR 회전 시
터치점이 그 반경의 원호로 퍼져 **면내 펼침이 크게 좋아진다**(§3 조건수 참조).

단, 초점거리가 고정이라 TCP 가 그 점에 정확히 가야 하므로 **리치 한계에서 yaw 다양성이 실제로 나오는지**
화면의 Yaw 범위 뱃지로 확인해야 한다.

## 2-2. 코봇 좌표계 — 공구만 맞추면 된다

**베이스 높이는 사람이 재지 않는다. 코봇이 잰다.** 터치할 때 기록하는 값은
`GetTcpPoseInBaseAsync(tool)` 이 관절 엔코더 + 정기구학 + 공구 오프셋으로 계산한
**BASE 기준 터치점**이다. 그 `Bz` 가 "그 점은 내 베이스보다 얼마나 아래인가"를 말해 준다.
운영자는 코봇이 알 수 없는 딱 하나 — 바닥이 어디인지(`q_z`) — 만 준다. 그래서 높이 측정은
표본마다가 아니라 **통틀어 한 번**이면 된다.

| 프레임 | 설정 |
|---|---|
| **작업물(User/WObj)** | **무관 — 손대지 않는다.** `GetForwardKinInBaseAsync` 가 활성 프레임이 0 이 아니면 `T_N` 으로 BASE 로 되돌린다. 베이스로 리셋할 필요도 없다 |
| **공구(Tool)** | **반드시 맞춘다.** 화면의 tool 번호 = 실제로 표적을 찍는 팁의 번호. 그 tool 의 TCP 가 미리 캘리브레이션돼 있어야 한다 |

- **tool 0 = 플랜지.** 프로브로 터치하면서 tool 0 을 쓰면 플랜지 위치가 기록돼 프로브 길이만큼
  통째로 틀어진다 — 사후 수치로는 검출 불가라 표본에 tool 번호를 기록해 혼용을 잡는다.
- 활성 공구가 무엇이든 무관하다 — 코드가 `P_T = P_active ∘ inv(offset_active) ∘ offset_T` 로 재프레임한다.
  단 활성 공구를 못 읽으면 기본값을 가정하고 경고를 남기므로(`활성 공구 미상 — 기본 공구 #N 가정`)
  **그 경고는 무시하면 안 된다.**
- 포즈 조회는 로봇을 움직이지 않고 enable/자동 모드도 요구하지 않는다. 조그에만 서보가 필요하다.

## 3. 표본 요구 — 두 가지가 서로 다르다

**이 둘을 같은 요구로 착각하면 안 된다.**

| 산출 대상 | 필요한 다양성 | 화면 지표 | 실패 | 경고 |
|---|---|---|---|---|
| rx, ry | 터치점이 평면 안에서 **비공선** — 정차 위치를 여러 방향으로 벌리면 yaw 를 안 바꿔도 충족 | 터치점 펼침 `√(λ₂/n)` | < 50 mm | < 300 mm |
| rz, tx, ty | **AMR yaw 다양성** | Yaw 범위 | < 15° | < 90° |

yaw 가 좁으면 해가 편향되는 게 아니라 **SLAM 잡음이 증폭**된다(증폭률 ≈ `1/(2·sin(펼침/2))`, 5° 펼침이면 약 11배).
레거시 평면 경로는 그 상태에서도 예외 없이 tx 가 100 mm 넘게 틀린 해를 돌려주는데 **잔차는 여전히 작다** —
운영자가 RMS 만 보고 합격으로 오인하는 것이 이 게이트의 존재 이유다
([회귀 테스트로 고정](../src/HD.AMR.Tests/MountCalibration3DTests.cs)).

### 표본 수 — 3개로 기울기를 믿으면 안 된다

몬테카를로 200회(AMR pose σ 5 mm/0.2°) 기준 rx/ry 오차:

| 표본 수 | 터치 σ=0.5 mm | 1.0 mm | 2.0 mm |
|---:|---|---|---|
| 3 | 0.42° | **0.81°** | 1.54° |
| 5 | 0.11° | 0.23° | 0.45° |
| 8 | 0.07° | 0.15° | 0.30° |

기울기 0.5° 오차 = 리치 1 m 에서 약 9 mm. **최소 5개, 권장 8개.**
표본 3개면 평면 적합이 정확해져 잔차가 0 으로 나오지만 그것은 정확도의 증거가 아니다 —
그래서 화면은 잔차와 별도로 **기울기 추정오차 σ** 를 보여 준다.

## 4. 현장 절차

**사전 조건**

1. AMR·코봇 연결, 조그 팝업에서 서보 ON, 코봇 오류 0.
2. 터치 공구의 TCP 가 이미 보정돼 있을 것 (`Laser Sensor ▸ 로봇 TCP 캘리브레이션`).
   **T_A_B 정확도는 TCP 정확도를 넘을 수 없다.**
3. 표적을 단단히 고정 — 접촉식이면 센터펀치 자국·원뿔 지그, 카메라 포인팅이면 벽 십자마크.
   무엇을 어디에 뒀는지 기록한다. **표적을 옮겼으면 기존 표본을 '전체 삭제' 한다.**

**측정**

4. **텔레스코픽을 완전 하강(기계적 원점)** 시키고 스트로크 0 확인 체크. 측정 내내 건드리지 않는다.
5. `q_z` 를 바닥 기준으로 실측해 입력하고 확인 체크(바닥 표적이면 0). 측정 근거를 기록한다.
6. AMR 을 정차시키고 `정지` 뱃지를 확인 → 조그로 표적 지시(접촉 또는 포커싱+중앙 정렬) → 확인 → `표본 캡처`.
7. AMR yaw 를 **30° 이상** 바꾸고 위치도 함께 옮겨 5~8회 반복. Yaw 범위가 90° 이상 되게 한다.
8. `Bz 산포` 가 3 mm 이내로 유지되는지 확인 — 넘으면 접촉이 일정하지 않으니 다시 한다.

**산출·적용**

9. `해 계산` → RMS ≤ 2 mm, 최대 ≤ 4 mm, 경고 없음을 확인. 평면 펼침 경고가 뜨면 장착판에 실제 기울기가
   있다는 뜻이니 CAD 와 대조한다.
10. `tx/ty/tz` 를 기계 도면과 대조. `tz` 는 **완전 하강 시 베이스 높이**여야 한다 —
    바닥에서 베이스 장착 플랜지 밑면까지 줄자로 재어 맞는지 확인한다.
11. `결과 적용` → 필요하면 수치 보정 → `T_A_B 저장`.
12. **홀드아웃 검증**: 표본에 없던 새 자세로 AMR 을 옮겨 같은 표적을 터치하고, 예측 맵 좌표가
    이전과 같은 점을 가리키는지 확인한다.
13. 그 다음에 `QR Pose Teaching` 흐름을 다시 돌린다(저장된 T_A_B 를 소비한다).

## 5. 안전

이 화면은 **AMR 도 코봇도 스스로 움직이지 않는다**. 하드웨어 접촉은 전부 읽기다 —
`AMRService.LatestStatus`(백그라운드 폴링 캐시), `GetTcpPoseInBaseAsync`(무동작: 관절 읽기 + 클라이언트측 FK),
로컬 SQLite 저장. AMR 이동은 작업자가 직접, 코봇 이동은 조그 팝업에서만 한다.

저장은 이 앱의 설정 DB 에만 기록되며 **코봇 컨트롤러나 HD_ACS 에는 자동으로 쓰지 않는다**.

캡처는 코봇 pose 를 5회 평균하고, 캡처 전후 AMR 이 5 mm / 0.2° 이상 움직였으면 표본을 버린다
(`QrLocalizationService.EnsureStationary` 와 같은 기준).

## 6. 잔차로는 잡히지 않는 오염

`MountSampleInspector` 가 메타데이터로만 검출한다:

| 증상 | 이유 |
|---|---|
| 표본 간 **공구 번호 혼용** | tool 0(플랜지)과 tool 1(프로브)을 섞으면 일부 터치점에만 수백 mm 바이어스가 들어가 그럴듯하지만 틀린 기울기로 위장된다. **사후 수치로는 검출 불가** |
| 모든 `Bz` 가 0 | Bz 를 기록하지 않던 구버전 표본 — rx/ry 가 0 으로 산출된다 |
| **텔레스코픽 스트로크 미기록/일부 기록** | 전 표본이 같은 높이였는지 확인할 근거가 없다. 다른 높이 표본이 섞이면 가짜 기울기가 된다 |
| 사실상 같은 AMR 자세 | 정보 중복, 정밀도에 기여하지 않음 |
| 표본이 여러 날에 걸쳐 있음 | 그 사이 재장착이 있었다면 섞어 쓰면 안 된다 |

## 7. 문제 해결

| 증상 | 확인 |
|---|---|
| "터치점이 거의 한 직선 위에 있습니다" | 정차 **위치**를 여러 방향으로 벌린다(yaw 만으로는 부족할 수 있다) |
| "AMR yaw 다양성이 부족합니다" | yaw 를 90° 이상 벌린다 |
| 평면 RMS 큼 (> 2 mm) | 접촉 정확도 또는 포커스 재현도, 바닥 요철로 인한 AMR 차체 기울기 |
| tz 가 작동거리만큼 어긋남 | 카메라 포인팅인데 tool TCP 가 초점이 아니라 광학 원점으로 정의돼 있다 |
| 평면내 RMS 큼 (> 25 mm) | 정차 후 SLAM pose 가 안정되기 전에 캡처했는지 |
| tz 만 크게 틀림 | `q_z` 입력값의 기준(바닥면). 줄자로 잰 값 그대로여야 한다 — 계산하지 않는다 |
| "표본 간 표적 높이가 다릅니다" | 표적을 옮긴 뒤 예전 표본과 섞였다 — 전체 삭제 후 재기록 |
| 기울기가 CAD 와 크게 다름 | 표본 간 텔레스코픽 스트로크가 같았는지 — 1 mm 편차가 0.32° 를 만든다 |
| 기울기 σ 가 큼 | 표본 수를 늘리거나 터치점을 더 넓게 벌린다 |
| 저장 후에도 QR 측정이 안 맞음 | T_T_C(핸드아이)와 공구 TCP 를 먼저 의심. `QrLocalization.SolveAmrPose` 의 `ZResidMm`·`RollDeg`·`PitchDeg` 잔차가 진단 지표다 |
