# ArUco 기반 코봇 장착 보정(T_A_B) 작업 절차서

바닥에 고정한 ArUco 마커를 Intel RealSense D435의 RGB 카메라로 여러 자세에서 촬영하여 다음 두 변환을 동시에 구하는 절차다.

- `T_A_B`: AMR 차체 프레임 **A** → 코봇 BASE 프레임 **B**
- `T_W_Q`: AMR SLAM 맵 프레임 **W** → ArUco 마커 프레임 **Q**

화면은 Desktop 앱의 `SETTINGS ▸ ArUco 장착 보정`이다.

- 화면: [ArucoMountCalibrationView.axaml](../src/HD.AMR.Desktop/Views/ArucoMountCalibrationView.axaml)
- 캡처: [ArucoMountCalibrationViewModel.cs](../src/HD.AMR.Desktop/ViewModels/ArucoMountCalibrationViewModel.cs)
- 계산: [ArucoMountCalibration.cs](../src/HD.AMR.App/Service/ArucoMountCalibration.cs)
- 검출: [ArucoPoseEstimator.cs](../src/HD.AMR.App/Communication/Vision/ArucoPoseEstimator.cs)

> 이 절차는 `T_W_D`(SLAM 맵 ↔ 도면) 보정이 아니다. `T_W_D`는 기존처럼 ACS에서 관리한다. 여기서는 AMR 차체 위에 설치된 코봇 BASE의 실제 장착 변환 `T_A_B`만 저장한다.

## 0. 화면 구조와 방법 선택

`T_A_B` 를 구하는 방법은 **두 가지**이고 서로 대안이다. 둘 다 `Calib.Mount.Pose` 에 같은 값을 쓴다.

| 메뉴 | 측정 수단 | 오차 체인 | 용도 |
|---|---|---|---|
| **`SETTINGS ▸ 장착 보정 (ArUco)`** | 카메라 (ArUco PnP) | `T_B_T` · `T_T_C` · `T_C_Q` — 변환 3개 | **운영 표준** |
| `SETTINGS ▸ 장착 보정 (접촉식)` | 물리 접촉 (터치 팁) | `T_B_T` — 변환 1개 | 카메라 없는 대안 · **독립 교차검증** |

접촉식은 카메라·OpenCV·Windows 가 전혀 필요 없고 체인이 짧아, ArUco 결과가 맞는지 확인할 수 있는
유일한 독립 수단이다. 특히 `T_T_C` 오차는 `T_A_B` 로 흡수되어 잔차로 드러나지 않으므로
(§3 참조) 초기 도입 시 한 번은 두 방법을 대조해 보는 것이 좋다. 절차는 `docs/TAB_CALIBRATION.md`.

### `장착 보정 (ArUco)` 은 한 페이지 2단계다

```
장착 보정 (ArUco)
  ├ 공통 설정 : Tool 번호 · ArUco ID · 마커 크기   ← 단일 원천
  ├ ① 핸드아이 측정 (T_T_C)   AX = XB
  └ ② 장착 보정 (T_A_B)       동시 추정   ← ① 완료 전에는 탭이 잠긴다
```

두 단계를 합친 이유는 **Tool 번호 정합**이다. `T_T_C` 는 특정 tool 의 TCP 기준이고 ②가 같은 기준의
`T_B_T` 와 합성하므로, 두 값의 tool 이 어긋나면 결과가 tool 오프셋만큼 틀린다 — 그런데
**잔차로는 전혀 드러나지 않는다.** 화면을 나누면 각자 입력해 어긋날 수 있으니 공통 설정 카드가
하나만 들고 두 단계에 밀어넣는다. 마커도 하나로 두 단계를 모두 처리한다.

## 1. 계산 원리

각 촬영 표본은 아래 좌표 체인을 만족해야 한다.

```text
T_W_A(i) · T_A_B · T_B_T(i) · T_T_C · T_C_Q(i) = T_W_Q
```

| 기호 | 의미 | 취득 방법 |
|---|---|---|
| `T_W_A` | SLAM 맵 기준 AMR pose | AMR 상태값 |
| `T_A_B` | AMR 차체 기준 코봇 BASE 장착 pose | 이 절차에서 산출 |
| `T_B_T` | 코봇 BASE 기준 선택 Tool pose | 코봇 정기구학 |
| `T_T_C` | Tool TCP 기준 D435 RGB 광학 프레임 pose | **`핸드아이 측정 (T_T_C)` 화면에서 AX=XB로 측정**(권장) 또는 Tool 2 설정·CAD값 |
| `T_C_Q` | RGB 카메라 기준 ArUco pose | ArUco 코너 + RGB 내부 파라미터로 PnP 계산 |
| `T_W_Q` | SLAM 맵 기준 고정 ArUco pose | `X/Y/Yaw`를 `T_A_B`와 동시 산출, `q_z`는 작업자 입력 |

바닥 마커는 수평이고 움직이지 않는다고 가정한다. 따라서 `T_W_Q`의 roll/pitch는 0으로 고정하며, 마커 중심의 바닥 기준 높이 `q_z`만 작업자가 입력한다.

### 좌표축 규약

- pose 순서: `[X, Y, Z, Rx, Ry, Rz]`
- 거리: mm
- 각도: degree
- 회전: ZYX RPY
- ArUco 마커: `+X`는 코드의 오른쪽, `+Y`는 코드의 위쪽, `+Z`는 인쇄면에서 카메라 방향
- 바닥에 위를 향하도록 설치한 마커의 `+Z`는 위쪽이어야 한다.

## 2. 준비물과 사전 조건

### 준비물

- Intel RealSense D435/D435i와 USB 3.0 연결
- 평탄하게 출력한 `DICT_4X4_50` ArUco 마커
- 마커 바깥 검은 사각형 한 변을 잴 수 있는 자 또는 캘리퍼스
- 마커를 바닥에 단단히 고정할 테이프 또는 고정판
- 바닥에서 마커 중심 인쇄면까지 높이를 측정할 도구

### 장비 조건

1. AMR, 코봇, D435가 모두 연결되어 있어야 한다.
2. D435 RGB 스트림과 RGB 내부 파라미터가 정상이어야 한다.
3. 코봇의 선택 Tool 좌표계가 정확해야 한다.
4. 텔레스코픽 리프트를 사용한다면 보정 전 과정에서 높이를 바꾸지 않는다.
5. 마커는 촬영 중 절대로 움직이지 않는다.
6. 측정 중 AMR SLAM localization이 안정되어 있어야 한다.

## 3. ① 단계 — T_T_C 측정

`T_T_C` 는 **① 핸드아이 측정 탭에서 측정**한다. ② 탭에서는 읽기 전용으로만 보이고 직접 입력할 수 없다 —
가정값을 넣으면 그 오차가 `T_A_B` 로 흡수되어 잔차로는 드러나지 않기 때문이다.

아래 두 절(권장 방식 / 다른 TCP인 경우)은 **참고용 배경**이다. 실제 값은 측정으로 확정한다.

### 권장 방식: Tool 2 원점 = RGB 광학 중심

Tool 2의 원점과 축을 D435 **RGB 카메라 광학 프레임**과 동일하게 설정했다면:

```text
T_T_C = [0, 0, 0, 0, 0, 0]
```

이론적으로는 `T_T_C` 가 0 이지만, **실제로 그렇게 설정됐다는 보장은 없다** — ① 단계로 확인하라.

### Tool 2가 다른 TCP인 경우

Tool TCP에서 RGB 광학 중심까지의 변환을 입력한다.

```text
T_T_C = [dx, dy, dz, dRx, dRy, dRz]
```

- 위치는 플랜지 외형이나 카메라 하우징 중심이 아니라 **RGB 렌즈의 광학 중심**까지 잰다.
- 카메라 축과 Tool 축이 완전히 평행하면 회전값은 0으로 둘 수 있다.
- 카메라가 X 방향으로 65 mm 떨어져 있어도 Tool 원점이 광학 중심이 아니라면 `dx=65 mm` 같은 위치 오프셋을 반드시 입력해야 한다.
- 축 방향이 반대거나 카메라가 돌아가 있으면 CAD의 좌표계 방향까지 확인하여 회전값을 입력한다.

> `T_T_C` 오차는 보정 과정에서 `T_A_B`로 흡수될 수 있다. 계산 RMS가 작아도 실제 장착값이 틀릴 수 있으므로 `T_T_C`를 먼저 확정해야 한다.

### 측정 절차 — ① 핸드아이 측정 탭

위 두 방식은 모두 **CAD 또는 가정값**이다. 렌즈의 광학 중심은 하우징 외형에서 잴 수 없고, "Tool 2 원점 = 광학 중심"도
실제로 그렇게 설정됐다는 보장이 없다. 그리고 바로 위 경고대로 **그 오차는 `T_A_B`로 흡수되어 RMS로는 드러나지 않는다.**

`장착 보정 (ArUco)` 의 **① 핸드아이 측정** 탭이 이 값을 **AX=XB 로 측정**한다.

**원리** — 마커를 고정하고 **AMR·리프트를 세워 둔 채 코봇 자세만** 바꾸면

```text
T_B_T(k) · T_T_C · T_C_Q(k) = T_B_Q  (상수)
  →  (T_B_T(j)⁻¹·T_B_T(k)) · X = X · (T_C_Q(j)·T_C_Q(k)⁻¹)      … AX = XB
```

`T_W_A` 가 식에서 **완전히 소거**되므로 `T_A_B` 를 몰라도 풀린다. 즉 `T_T_C` → `T_A_B` 순서가 순환 없이 성립한다.
해법은 Park & Martin(1994): 회전은 `M = Σβαᵀ`, `R_X = (MᵀM)^(−1/2)Mᵀ`, 병진은 `(R_A−I)t_X = R_X t_B − t_A` 최소자승.

**절차**

1. 이 절차용 마커는 §4의 바닥 ArUco를 그대로 쓴다(별도 설치 불필요).
2. AMR을 정차시키고 **리프트를 고정**한다. 리프트는 AMR과 코봇 베이스 사이에 있어 움직이면
   마커가 베이스 기준으로 이동하고 "상수" 전제가 깨진다 — 화면이 리프트 높이 변화를 감시해 경고한다.
3. `Tool 번호`는 **공통 설정 카드**에 하나만 있어 ②와 자동으로 일치한다(기본 2). 카메라에 컨트롤러 TOOL이 없으면 `0`(플랜지)을 써도 된다.
4. 조그로 코봇 자세를 바꿔가며 **8~12회** 캡처한다.
5. `산출` → `결과 적용` → `T_T_C 저장`. 저장되면 ② 탭의 잠금이 풀린다. 저장 키는 ②가 읽는 것과 **동일**(`Calib.HandEye.Pose`)하다.

**⚠ 성패는 표본 수가 아니라 회전축 다양성이다**

AX=XB는 회전에서 정보를 얻는다. 모든 상대 회전축이 평행하면 `MᵀM`이 특이해져 **표본을 20개로 늘려도 풀리지 않는다.**
손목을 **서로 평행하지 않은 2개 이상 축**으로 각각 ±20~30° 돌려야 한다. 위치만 옮기는 자세는 회전 정보를 0 제공한다.
화면은 회전축 다양성을 지표로 보여 주고, 부족하면 계산 전에 거부한다.

180° 부근 상대 회전 쌍은 축 부호가 원리적으로 모호하므로(+π ≡ −π) 솔버가 자동으로 제외한다.

**합격 기준** — 회전 잔차 RMS < 1.0°, 병진 잔차 RMS < 5 mm, 회전축 다양성 경고 없음.

## 4. ArUco 마커 설치 및 입력

프로젝트에 [A4 인쇄용 ArUco 마커](aruco/aruco_4x4_50_id0_120mm_A4.svg)가 포함되어 있다. 이 파일은 `DICT_4X4_50`, **ID 0**, 검은 사각형 바깥 한 변 **120 mm**이다. SVG를 A4에 **실제 크기/100% 배율**로 인쇄한다. 용지 맞춤, 여백 자동 조정, 확대·축소는 끈다. 하단의 100 mm 확인 눈금과 검은 사각형 한 변을 자로 재고, 인쇄 후 실측한 한 변 길이를 화면에 입력한다. 흰 여백과 설명 글자를 포함한 크기를 입력하면 안 된다.

1. 제공 마커를 쓴다면 `DICT_4X4_50`의 ID `0`을 선택한다. 다른 마커를 쓰면 해당 사전과 ID를 먼저 확인한다.
2. 마커를 휘지 않는 평판에 부착한다.
3. 마커 인쇄면이 수평이 되도록 바닥에 고정한다.
4. 검은 사각형의 바깥 한 변 길이를 mm로 측정한다.
5. 바닥 기준 마커 중심 인쇄면의 높이 `q_z`를 측정한다.
   - 바닥에 직접 부착: 일반적으로 `q_z = 0 mm`
   - 10 mm 판 위에 부착: 인쇄면 높이를 실측하여 약 `10 mm`
6. 화면에 `ArUco ID`, `마커 크기`, `마커 q_z`를 입력한다.
7. 값과 기준면을 다시 확인한 뒤 `q_z 확인`을 체크한다.

현재 화면에서 지원하는 사전은 `DICT_4X4_50`, ID 범위는 0~49다. 다른 사전의 마커는 검출되지 않는다.

## 5. 표본 수집

### 권장 표본 구성

| 항목 | 계산 최소 조건 | 현장 권장값 |
|---|---:|---:|
| 총 표본 수 | 8개 | 15~40개 |
| AMR 위치 범위 | 150 mm 이상 | 300 mm 이상 |
| AMR yaw 범위 | 20° 이상 | 60~90° 이상 |
| AMR 정차 위치 | 제한 없음 | 4곳 이상 |
| 위치별 카메라 시점 | 제한 없음 | 3~5개 |
| ArUco 재투영 오차 | 3 px 이하 | 평균 1.5 px 이하 |

AMR 위치와 yaw 다양성이 `T_A_B`의 관측성을 만든다. 코봇 자세 변화는 동일 마커를 영상의 여러 위치와 각도에서 보게 하여 카메라 측정 편향을 줄인다.

### 한 표본을 캡처하는 방법

1. AMR을 마커 근처에 정차한다.
2. 코봇을 움직여 D435 RGB 영상에 마커 전체가 보이게 한다.
3. 네 모서리가 잘 보이고 반사, 그림자, 흔들림이 없는지 확인한다.
4. AMR이 완전히 정지한 뒤 `현재 자세에서 ArUco 캡처`를 누른다.
5. 화면은 1.2초 동안 AMR pose 변화를 검사한다.
   - 위치 변화가 5 mm를 초과하거나 yaw 변화가 0.2°를 초과하면 캡처를 거부한다.
6. 검출된 마커 ID와 재투영 오차를 확인한다.
7. 같은 AMR 위치에서 코봇의 거리·기울기·영상 내 마커 위치를 바꿔 3~5개를 촬영한다.
8. AMR을 다른 위치와 방향으로 이동한 뒤 반복한다.

### 자동 계측 — AMR·코봇 자동 이동 (권장)

`AMR·코봇 자동 계측`을 누르면 다음을 스스로 수행한다. 작업자는 **시작 자세(마커가 FOV 에 보이는
코봇 자세)만** 잡아 주면 된다.

1. 활성 좌표계를 (지정 Tool / 베이스) 로 정규화하고, 현재 코봇 자세를 **주행 안전자세**로 기억한다.
2. 시작 자세에서 표본을 찍고, 코봇을 ±틸트시켜 같은 정차점에서 시점을 늘린다.
3. 코봇을 주행 안전자세로 되돌린 뒤 **AMR 을 다음 정차점으로 자동 주행**시킨다
   (좌/우/전/후 4곳, 시작 yaw 기준 ±yaw 편위).
4. 정차하면 마커가 **직전과 같은 월드 위치**에 오도록 코봇을 재조준하고 촬영한다.
5. 4곳을 돌고 시작 자세로 복귀한다.

**AMR 주행 인터페이스**

| 항목 | 내용 |
|---|---|
| 주행 명령 | REST `POST /api/v3/robot/go` (x, y, rz, `stopFlag=true`) |
| 선행 정지 | 매 이동 전 `POST /api/v3/robot/state` — `/go` 는 **큐 추가**라 이전 목적지가 남으면 오경유한다 |
| 정차 판정 | Modbus 작업상태 `Idle` + pose 가 연속 3회 정지(5 mm / 0.2° 이내) |
| 중지 | `자동 계측 중지` → REST 정지 + 코봇 즉시 정지 |

> **⚠ Modbus `PoseSearch`(Holding 20~26)는 주행 명령이 아니라 재측위다.** 좌표를 쓰고 활성화하면
> 로봇은 제자리에 있고 **자기 위치 추정만 그 좌표로 옮긴다**. 보정은 "AMR 이 실제로 어디 있는가"를
> 표본 기준으로 쓰므로, 재측위로 만든 pose 를 믿으면 잔차에 드러나지 않는 조용한 오보정이 된다.
> 자동 계측은 이 레지스터를 쓰지 않는다.

**정차 정밀도는 요구하지 않는다.** 표본의 AMR 기준은 지령 좌표가 아니라 **실제 정차 pose**(Modbus 실측)다.
목표에서 500 mm / 10° 넘게 벗어나면 마커가 FOV 를 벗어나므로 그 정차점만 건너뛴다.

**실패해도 전체가 멈추지 않는다.** 한 정차점의 주행·검출이 실패하면 그 곳만 건너뛰고 다음으로 간다
(최소 표본 8개·정차점 3곳을 만족하면 산출 가능).

**전제 조건** — AMR 이 드라이브 모드이고, 주행 정지가 해제돼 있고, 오류 코드가 0 이어야 한다.
이동 명령을 수리하고도 15초간 움직이지 않으면 "명령 미수행"으로 보고 중단한다
(그 상태로 계속하면 같은 자세의 표본만 쌓여 관측성이 생기지 않는다).

### 좋은 카메라 시점

- 마커 네 모서리가 모두 영상 안에 있다.
- 마커가 너무 작지 않으며 초점이 맞는다.
- 카메라가 마커 정면만 보는 표본으로 채우지 말고 적당한 경사 시점도 섞는다.
- 영상 중앙뿐 아니라 좌우·상하 영역도 사용한다.
- 극단적으로 비스듬하여 한 변이 거의 선처럼 보이는 시점은 피한다.

> 표본은 현재 페이지 메모리에만 보관된다. 페이지를 나가거나 앱을 종료하면 사라지므로 한 번의 작업 세션에서 수집과 산출을 완료한다.

## 6. 산출, 판정 및 저장

1. 표본이 8개 이상이고 위치/yaw 조건을 충족하면 `T_A_B + T_W_Q 동시 산출`을 누른다.
2. 다음 결과를 확인한다.
   - 위치 RMS
   - 회전 RMS
   - 추정 마커 `W.X`, `W.Y`, `W.Yaw`
   - 산출된 `T_A_B`
3. 산출값을 기존 값 및 기계 CAD와 비교한다.
4. 결과가 타당하면 `산출값 적용`을 누른다.
5. 편집란에 들어간 값을 다시 확인한다.
6. `T_A_B 저장`을 누른다.

`산출값 적용`만 누르면 저장되지 않는다. 반드시 `T_A_B 저장`까지 눌러야 설정 DB의 `Calib.Mount.Pose`가 변경된다. 저장값은 HD_AMR 앱에서 사용되며 코봇 컨트롤러나 HD_ACS에 자동 전송되지 않는다.

### 권장 합격 기준

아래 값은 초기 현장 기준이며 실제 SLAM과 카메라 반복도를 측정해 조정한다.

| 지표 | 권장 | 조치 필요 |
|---|---:|---:|
| 위치 RMS | ≤ 10 mm | > 20 mm |
| 최대 위치 오차 | ≤ 20 mm | > 40 mm |
| 회전 RMS | ≤ 0.5° | > 1.0° |
| 평균 재투영 오차 | ≤ 1.5 px | > 3 px 표본은 캡처 단계에서 거부 |
| 기존 `T_A_B` 대비 변화 | CAD/실측 허용 범위 | 수십~수백 mm 또는 수° 변화 시 원인 확인 |

작은 RMS만으로 합격시키면 안 된다. 잘못된 `T_T_C`, 마커 크기 또는 `q_z`가 모든 표본에 동일하게 적용되면 RMS는 작으면서 `T_A_B`는 틀릴 수 있다.

## 7. 저장 후 독립 검증

보정에 사용하지 않은 AMR 위치와 코봇 자세에서 검증한다.

1. AMR을 새 위치와 새 yaw로 이동한다.
2. 같은 고정 ArUco를 다시 촬영한다.
3. 저장한 `T_A_B`와 `T_T_C`로 각 관측의 `T_W_Q`를 계산한다.
4. 모든 관측에서 마커의 `X/Y/q_z/Yaw`가 같은 값으로 재현되는지 확인한다.
5. 가능하면 줄자 또는 도면 기준으로 AMR-마커 상대 위치도 대조한다.
6. 텔레스코픽을 사용하는 경우 보정 높이와 실제 운용 높이의 `tz` 처리도 확인한다.

검증 표본은 계산 표본과 분리해야 한다. 계산에 사용한 표본의 RMS는 학습 오차이고, 새 자세의 재현 오차가 실제 운용 성능에 더 가깝다.

## 8. 실패 메시지와 조치

| 메시지/증상 | 원인 | 조치 |
|---|---|---|
| 캡처 버튼 비활성 | AMR/코봇/D435 미연결, RGB 내부 파라미터 없음, `q_z 확인` 안 함 | 상단 연결 뱃지와 입력값 확인 |
| `ID N 마커를 찾지 못했습니다` | ID/사전 불일치, 가림, 흐림, 조명 불량 | `DICT_4X4_50` 및 ID 확인, 거리·조명 조정 |
| `재투영 오차가 너무 큽니다` | 마커가 휘었거나 너무 작음, 모션 블러, 크기 입력 오류 | 마커 평탄도·초점·실측 크기 확인 |
| `AMR이 정지하지 않았습니다` | SLAM pose가 계속 변함 | 완전 정차 후 localization 안정 대기 |
| `최소 8개 표본` | 표본 부족 | 다양한 위치와 시점에서 추가 촬영 |
| `yaw 범위가 20° 미만` | 방향 다양성 부족 | AMR 방향을 크게 바꿔 추가 촬영 |
| `위치 범위가 150 mm 미만` | 위치 다양성 부족 | AMR 정차 위치를 더 넓게 분산 |
| `정규방정식이 특이합니다` | 비슷한 자세만 반복하여 관측 불충분 | AMR 위치/yaw와 코봇 시점을 모두 변경 |
| RMS는 작지만 CAD와 크게 다름 | `T_T_C`, 마커 크기, `q_z`, 축 방향 오류 | 입력값과 Tool 2 정의부터 재검토 |
| 위치마다 결과가 일정 방향으로 달라짐 | D435 내부 파라미터/왜곡, Tool 2 회전, SLAM 편향 | 영상 영역을 다양화하고 카메라/Tool 캘리브레이션 확인 |

## 9. 안전 및 운용상 주의

- 이 화면은 AMR이나 코봇을 자동 이동시키지 않는다.
- AMR 이동은 작업자가 수행하고, 코봇 이동은 별도 조그 기능으로 수행한다.
- 캡처 동작은 AMR pose, 코봇 Tool pose와 RGB 프레임을 읽을 뿐이다.
- 코봇 조그 중에는 작업자와 주변 인원을 안전구역 밖에 둔다.
- 마커가 움직였거나 D435/코봇/장착 브래킷을 재조립했다면 기존 표본과 결과를 재사용하지 않는다.
- D435 RGB 해상도나 내부 파라미터가 변경되면 다시 검증한다.
- `T_A_B` 저장 후에는 QR 정차 티칭 등 이 값을 사용하는 기능을 다시 검증한다.
